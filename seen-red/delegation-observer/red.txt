SELF-INFLICTED INSTANCE OF THE SAME CLASS, CAUGHT WHILE DRAFTING THIS FIX (stated honestly, not
swept past): the first draft of this fix's own docstring prose wrote the illustrative surrogate
example as a bare single-backslash `\ud800` inside the hook's own (non-raw) module docstring --
Python's tokenizer decodes that at COMPILE time into an actual lone-surrogate code point landing
in the module's own `__doc__` constant, which made the module itself fail to import
(`runpy`'s `_get_code_from_file` raised the identical `UnicodeEncodeError`, merely from importing
the file, before any hook logic ran) -- the worst possible instance of the class. Caught by
running `python3 -m py_compile` and an `ast`-based docstring-surrogate check before calling the
fix done; every surrogate example in the shipped docstring is double-backslashed so it reaches
`__doc__` as inert text.
